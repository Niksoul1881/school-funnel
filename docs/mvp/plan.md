# MVP платформы: план и границы

Версия 0.1 · 2 ноября 2026 · рабочая тетрадь

## 1. Цель MVP

Собрать **рабочий вертикальный срез** платформы, который можно показать команде и первому бета-ученику:

> Человек заходит в браузер, выбирает шаблон, отвечает на 8 вопросов, получает проект с файлами, общается с агентом, видит превью бота и нажимает «Опубликовать».

Критерий готовности MVP:

- [x] Регистрация и вход, личный кабинет.
- [x] Каталог из 7 шаблонов (боты, агенты, мини-аппы).
- [x] Бриф из 8–11 полей → создание проекта с файлами.
- [x] Чат с агентом, который реально меняет файлы проекта.
- [x] Просмотр файлов и превью (эмулятор Telegram / мини-апп).
- [x] Деплой бота: проверка токена через Telegram `getMe`, статус, логи.
- [x] Токенный баланс, пакеты и списание за запросы (демо-пополнение).
- [x] 6 уроков тест-драйва с прогрессом.
- [x] Админка: пользователи, проекты, продано/использовано токенов, маржа.
- [x] Всё запускается одной командой на Windows.

**Статус на 2 ноября 2026:** вертикальный срез собран в `platform/` и задеплоен на сервер. Интерфейс — VS Code-workbench: activity bar, дерево файлов с папками и иконками типов, вкладки, редактор, AI-панель, терминал. **Реальный DSH-агент включён**: он создаёт и меняет файлы в проекте, usage списывается по фактическим токенам. 24/7-рантайм ботов пока выключен — нужен токен и контейнерный рантайм.

## 1.1 Монетизация: токены, не подписка

Решение: **не месячная подписка, а пакеты токенов**. Владелец покупает API-токены оптом, ученик покупает пакет токенов, платформа списывает **фактические токены запроса** (input + output) с баланса.

- Пакеты: 1 млн — 390 ₽, 5 млн — 1 690 ₽, 10 млн — 2 990 ₽.
- Себестоимость ориентира: ~150 ₽ за 1 млн (DeepSeek flash, микс input/output).
- В счётчике ученика: доступно / потрачено / история операций.
- В админке: продано токенов, использовано, выручка, себестоимость, маржа.
- Демо-пополнение работает без реального платежа; Robokassa/Stars — следующий слой.

## 3. Пользовательский путь для демо

1. Открыть `http://127.0.0.1:8000` → лендинг/вход.
2. Войти демо-аккаунтом (`demo@school.local` / `demo1234`).
3. Дашборд: токены 1 млн, уроки, проекты.
4. «Новый проект» → выбрать «Бот-визитка с AI».
5. Бриф: салон «Лотос», услуги, цены, тон, FAQ, контакт.
6. Проект: файлы уже сгенерированы, превью бота работает.
7. В чате: «Добавь меню: Услуги, Записаться, Цены, Связаться» → агент отвечает и меняет `content.json`.
8. «Опубликовать» → вставить токен тестового бота → `getMe` → статус «работает» (в MVP — валидация + запись, без 24/7 рантайма).
9. «Уроки» → пройти 5 уроков и финал, прогресс сохраняется.
10. Админка → видно пользователя, проект, токены и маржу.

## 4. Архитектура MVP

```
Браузер (SPA, vanilla JS)
   │ JSON / SSE
   ▼
FastAPI (Python 3.13)
   ├── SQLite (users, projects, files, messages, deployments, usage, lessons)
   ├── Agent adapter
   │     ├── mock: правила + шаблоны (по умолчанию)
   │     └── dsh: subprocess `dsh --profile headless --json`
   ├── Telegram: getMe
   └── Статика: HTML/CSS/JS без сборки
```

Почему так:

- **FastAPI + SQLite** — уже установлены, запускаются без npm и сборки, легко переносятся на VPS.
- **Vanilla JS SPA** — нет зависимости от Node/React, быстрее собрать и показать; позже можно переехать на Next.js.
- **DSH-headless** — реальный агент: читает/создаёт/меняет файлы и списывает фактический usage. Mock остаётся fallback, если нет ключа или DSH.
- **Один процесс** — просто запускать и отлаживать.

## 6. Что реально, а что mock

| Компонент | MVP | После MVP |
|---|---|---|
| Агент | DSH-headless: реальные файлы + фактический usage; mock — fallback | сессии, стриминг, песочница на проект |
| Деплой | `getMe` + запись + имитация лога | контейнер, webhook, health-check, 24/7 |
| Оплата | демо-пакеты токенов | Robokassa/Stars, вебхуки, возвраты |
| Хостинг | VPS + Docker + Caddy + HTTPS | домен, мониторинг, бэкапы |
| Превью | эмулятор в браузере | реальный Telegram WebApp |

Это нормально для MVP: мы проверяем **продуктовую механику**, а не строим сразу прод-инфраструктуру.

## 7. Безопасность и ограничения MVP

- Пароли — Argon2 (fallback scrypt).
- Сессия — HttpOnly cookie, случайный токен, хранение хеша.
- CSRF — SameSite=Lax + проверка Origin для POST.
- Токены ботов — Fernet-шифрование, ключ в `.env` (не в git).
- SQL — только параметризованные запросы.
- Файлы проекта — в БД; агент не имеет доступа к файлам вне проекта.
- MVP не предназначен для публичного интернета без HTTPS и аудита.
