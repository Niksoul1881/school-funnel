# Quality bar: как вести этот проект

Файл-напоминание для агента и для меня. Здесь зафиксированы ошибки, которые уже стоили времени, и правила, которые нельзя терять.

## 1. Один источник правды

Для клиентского бота тексты и услуги должны жить в `content.json` проекта. Движок не должен держать второй захардкоженный вариант приветствия, цен или названий.

Перед ответом «готово» проверить цепочку целиком:

```text
агент → content.json → синхронизация → engine → сообщение в Telegram
```

Проверять каждое поле, которое видит клиент: приветствие, адрес, услуги, цены, слоты, контакт. Не проверять только цену и делать вывод, что работает всё.

## 2. Не заставлять пользователя редактировать JSON руками

Если в проекте есть AI-агент, задача формулируется ему в чат. Ручной `content.json` — только резервный путь.

## 3. Архитектура ботов

- Один общий процесс и один движок на все тенанты.
- У каждого бота свой токен, бриф, сессии и брони.
- Изменение кода движка влияет на всех после перезапуска.
- Изменение `content.json` одного проекта влияет только на его бота.
- Не обещать «индивидуальный сервер» там, где его нет.

## 4. Производительность

- Не сериализовать и не писать весь FSM/state на каждое сообщение.
- Запись состояния — debounce 0.4–1.5 секунды, атомарная замена файла.
- Не блокировать event loop синхронной записью в горячем пути.
- Конфиг тенанта кэшировать, не читать `tenants.json` на каждый апдейт.
- Не делать лишних Telegram-сообщений и лишних HTTP-запросов.
- Тяжёлые операции — в отдельный поток/задачу, не в обработчике сообщения.

## 5. UX

- Не оставлять в истории старые кнопки, ведущие в устаревший сценарий.
- Чистить сообщения бота по шагам, но не удалять сообщения пользователя.
- Не показывать занятые и прошедшие слоты.
- Не принимать «любое» время: проверять формат, слот, занятость и дату.
- Не сбрасывать шаг после ошибки — оставаться на том же шаге и объяснять причину.
- История диалога должна быть доступна отдельной кнопкой, а не теряться.

## 6. Картинки и медиа

- WebP/JPEG, не PNG для фотографий.
- Проверять, как картинка выглядит в реальном Telegram на телефоне.
- Не рисовать «красивые» карточки, если текст на них не читается.

## 7. Перед финальным ответом

- Запустить тесты и QA.
- Проверить реальный сценарий, а не только «код скомпилировался».
- Проверить, что бот запущен после перезапуска.
- Ответить на вопрос пользователя по существу, без инструкций, которые он не просил.

## 8. Уроки из этой сессии

- FSM-состояние нельзя хранить как `state.state` с префиксом `@:` и потом грузить как `State(...)` без нормализации.
- Скрывать токен в учебном скриншоте можно, но если он уже отозван — это лишнее.
- Кнопка «взять готовый токен» опасна: токен уже занят другим polling-процессом.
- Нельзя считать, что `content.json` и движок читают одни и те же поля.
- Проверка «цена обновилась» не означает «приветствие обновилось».
